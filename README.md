# 47_ギャンブル — 競艇 収益化モデル

競艇（ボートレース）の着順分布を予測し、パリミュチュエル市場のオッズに対して
統計的に有意な優位を持つことを証明するプロジェクト。

解釈性より精度を優先する。手法選択の基準は「ホールドアウトで転移したか」の一点。

---

## 1. 目的と成功の定義

**ゴール**：封印ホールドアウト期間において、回収率 > 100% を統計的に有意に示す。

実弾投票はしない。自動投票インフラは構築しない。証明が成果物。

### 前提となる数字

| 項目 | 値 |
|---|---|
| 競艇の払戻率 | 単勝・複勝 約80% / 連系（2連単・3連単等）約75% |
| ランダム購入の期待回収率 | 約75%（連系） |
| 1号艇の平均勝率 | 約55%（会場差が大きい） |
| 年間レース数 | 約4万（1日平均110） |

**友人の70%はモデルの失敗ではなく、控除率に負けているだけ**。ランダム購入（75%）
を下回っているので、モデルが価値を生んでいないか、人気薄バイアスで損している。
「精度」ではなく「オッズに対する優位」が唯一の目標指標であることの証拠。

## 2. アーキテクチャ

Bill Benter（香港競馬）の2段構成を採用する。fundamental 単体でも市場単体でも勝てず、
合成して初めて勝つ、という構造。

```
[第1段] fundamental モデル  ※オッズを一切見ない
   能力データ + 直前情報 → 6艇の強さ s_i
        ↓
   Plackett-Luce で 120通りの3連単確率に展開
   （1着 softmax → 残り5艇で再softmax → …）
        ↓
[第2段] 合成モデル
   入力: log(fundamental確率), log(市場含意確率)
   出力: 最終確率 P
        ↓
[第3段] 賭け判定
   EV = P × オッズ  → EV > 閾値 の目のみ購入
```

### なぜオッズを特徴量に直接入れないか

オッズは単体で最強の予測変数（数万人の集合知）。GBM に直接投入すると log-loss は
最良になるが、モデルの中身は市場の写しになる。自分の確率 P ≒ 市場含意確率となり、
EV = P × オッズ ≒ 0.75 に固定される。**どの目を買っても控除率ぶん負ける。**
「精度は良いのに勝てない」の典型的な原因。

### 市場含意確率の作り方

パリミュチュエルなのでオッズの逆数を正規化する。3連単なら `Σ(1/odds) ≈ 1.33`
（= 1/0.75）なので、これで割って和を1にする。

ただし favorite-longshot bias（人気薄が過剰に買われ期待値が低い）が乗っているので、
`p ∝ (1/odds)^α` の power 変換で α を学習させる余地がある。第2段が吸収する想定。

### 120通り確率の生成 — 段階的に高度化

1. **Plackett-Luce（ベースライン）** — 6個の強さから120通りを一貫生成。軽い。
   ただし IIA 仮定を置き、競艇ではこれが露骨に破れる（1号艇が逃げ切ると2着は
   2号艇より3号艇が来やすい等、決まり手により2着以下の分布が変わる）。
2. **段階条件付き GBM（拡張）** — 1着モデル → 「1着が艇i」を条件に入れた2着モデル
   → 3着モデル。PLの一般化で決まり手由来の相互作用を学習できる。

拡張の寄与は walk-forward 上の ablation で測る。改善しなければ PL に戻す。

**当初計画の168,561ページ（約24万ページ）一括取得は、この条項に真正面から当たる。**

#### (2) Akamai Bot Manager が稼働している（サイトは「甘く」ない）

`odds3t` のレスポンスヘッダに商用ボット検知の痕跡：

```
x-akamai-transformed: 9 3374 0 pmb=mRUM,2
set-cookie: _abck=...      ← Akamai Bot Manager
set-cookie: bm_sz=...      ← 同上
```

判定はエッジ（CDN）側。閾値を超えるとオリジンに届く前に遮断され、遮断単位は
IP＋フィンガープリント。**ここは WSL2 の家庭回線なので自宅IPごと飛ぶ。**
テレボート（ネット投票）も同じ `.boatrace.jp` 配下のため、実弾投票側まで
巻き添えを食う可能性がある。4,500件で無事だったのは安全の証明ではなく未到達なだけ。

#### (3) 「1req/秒なら安全」は成り立たない — 岡崎市立中央図書館事件

2010年、公開の蔵書検索を**約1秒に1回**（本プロジェクトとほぼ同ペース）で
自動取得していた男性が偽計業務妨害の疑いで逮捕、約20日勾留。後に図書館側ソフトの
バグが原因と判明し起訴猶予となったが、逮捕の事実は残った。

**技術的な行儀の良さと法的リスクは別の軸**。運営が「業務に支障」と判断すれば成立しうる。

#### (4) 著作権は本件の主たる制約ではない

著作権法30条の4 が情報解析目的の複製を広く権利制限の対象にしているため、

効くのは (1) の規約違反（契約）と (3) の業務妨害（刑事）で、どちらも30条の4の射程外。

#### 結論と方針

| 経路 | 扱い |
|---|---|
| `www1.mbrace.or.jp/od2/`（LZH一括） | **公認のバルク配布channel。堂々と使う** |
| `boatrace.jp/owpc/pc/race/odds3t`（オッズ板） | **規模を絞る。全件取得はしない** |

3連単120通りのオッズ板は公式一括配布に存在しない（`payouts.parquet` にあるのは
`bet_type/combo/amount/ninki` ＝**的中目のみ**）。スクレイピング以外の入手経路がない
本物の穴。よって「取らない」ではなく「**必要最小限だけ取る**」が方針。

**採用方針 A（2026-07-20 暫定決定、再検討の余地あり）**：全件ではなく標本にする。
エッジの有無を検定したいだけなら母集団は不要で、§5 の見積り（3連単で約9,200点）から
逆算して数千〜1.5万レースあれば ROI の信頼区間は実用幅に収まる。10万件超は統計的にほぼ無駄。

**併用検討**：サイトポリシーの問い合わせフォームから研究目的・非商用・レート・
総件数を明記して照会する。時間はかかるが唯一リスクをゼロにする道。

## 5. 検証設計

TVT と同じ CV / LB 構造を持ち込む。

| TVT | 本プロジェクト |
|---|---|
| GroupKFold CV | walk-forward（古い2年、何度でも見てよい） |
| LB 提出 | **封印ホールドアウト（直近1年）** |
| 提出回数 | **開封回数に上限を設け、記録に残す** |

**開封回数の管理は必須**。5回見て一番良かったものを選んだ時点で、それは実質
ホールドアウトではなく CV。各回の日付・対象モデル・結果をログに残す。

### 必要ベット数の見積もり

ベット1点のリターンは「ほぼ0、たまに巨額」の歪んだ分布で、標準偏差はおよそ
`√(p(1-p)) × 配当`。必要サンプル数は `(1.96σ / 超過分)²` で効くため、
**配当が上がると必要検証数が二乗で膨らむ**。

| 券種 | 想定的中率 | 想定配当 | 1点のσ | 回収率120%を有意に示すのに必要 |
|---|---|---|---|---|
| 単勝 | 33% | 3倍 | 約1.4 | 約200点 |
| 2連単 | 10% | 12倍 | 約3.6 | 約1,300点 |
| 3連単 | 2% | 70倍 | 約9.8 | **約9,200点** |

封印1年 = 4万レース。EVフィルタ通過15%・1レース5点なら約3万ベット。
**3連単でも封印1年で有意判定が成立する。**

有意性の判定はブートストラップで行う（分布が正規から遠いのでt検定は不適）。

### バックテストに必ず入れる補正

素の確定オッズで回すと必ず楽観側に外れる。以下を織り込む。

1. **自己インパクト** — 自分の投票がプールに入りオッズが下がる（後述）
2. **締切ズレ** — 実際の投票は締切1〜2分前だが、そこから締切までに大口が入って
   オッズは動く。確定オッズでのバックテストは「実際には買えなかった有利なオッズ」
   で買ったことになる。下方補正を入れる。

## 6. 資金管理

**検証は全点1円の均等賭け**。回収率がそのままモデルの優位を表し、資金管理の巧拙と
分離できる。優位が確認されてから 1/4〜1/2 Kelly を載せる。確率推定に誤差がある以上、
フル Kelly は破産する。

### 市場インパクト（この戦略がスケールしない理由）

オッズの定義から、ある目への投票額は逆算できる：

```
その目の投票額 = 総売上 × 0.75 / オッズ
```

一般戦1レースの3連単売上を3,000万円と仮定、100倍の目：

- その目に入っている金 = 3000万 × 0.75 / 100 = **22.5万円**
- **1万円** 追加 → 新オッズ 95.8倍（**−4%**）
- **10万円** 追加 → 新オッズ 69.4倍（**−31%**）

**優位が +20% あっても、10万円入れた瞬間に優位は消えて負けに転じる。**
人気薄ほどプールが薄く影響が激烈。

要件：
- 賭け金上限は**その目の推定投票額の数%**（絶対額ではなく相対）
- バックテストは自己インパクト込みのオッズで回す
- **この戦略には資金上限がある。スケールしない。**

## 7. 中間ゲート（撤退基準）

先に数値で固定する。ギャンブルのバックテストは分散が大きく、「もう少しで勝てそう」
が永遠に続く構造を持つ。いつでも「たまたま悪かった」と言えてしまう。

| ゲート | 内容 | 不合格時の行動 |
|---|---|---|
| **G0** | **健全性検算**：①1号艇勝率≈52-55%と会場差（江戸川最低・徳山最高）②人気順位と的中率の単調性 ③odds×100=払戻金の一致 | 一致しないならデータかコードのバグ。先へ進まない |
| **G1** | fundamental 単体の log-loss が素朴事前（会場別1号艇勝率等）を有意に上回る | 特徴量・前処理の問題。モデルをいじる前にデータを疑う |
| **G2** | **合成モデルが市場含意確率単体を out-of-sample log-loss で有意に上回る** | **最重要ゲート**。上回らなければ優位はゼロ。賭け方をいくら試しても無駄。モデルをいじるのをやめてデータ／特徴量を増やす |
| **G3** | walk-forward の ROI（自己インパクト・締切ズレ補正込み、均等賭け）> 95% | 封印を開けない |
| **G4** | 封印ホールドアウト ROI > 100%、ブートストラップで p < 0.05 | プロジェクト終了（成功 or 失敗として記録） |

**G2 が最短の判定路**。賭けのシミュレーションを書く前に、優位の有無が分かる。
EV計算・資金管理・インパクト補正は全て G2 通過後でよい。

### G2 予備判定の結果（2026-07-20、4,901レース）— **不合格**

手持ちオッズ34日分で `src/g2_prelim.py` を実行。fundamental は 2022-07〜2023-06 で
学習し 202307-08 を予測（厳密に時系列OOS）、合成器のみレース単位5-fold CV。

| モデル | log-loss |
|---|---|
| market（q そのもの） | 1.1686 |
| market^b（power補正、b=1.065） | 1.1671 |
| fundamental 単体 | 1.2541 |
| combined（a=0.017, b=1.050） | 1.1675 |

| 比較 | 差 | 95%CI | 判定 |
|---|---|---|---|
| **combined − market（G2本体）** | −0.0011 | [−0.0026, **+0.0005**] | **FAIL**（CIが0を跨ぐ） |
| combined − market^b | +0.0004 | [+0.0001, +0.0007] | FAIL（合成のほうが**有意に悪い**） |
| market^b − market | −0.0015 | [−0.0030, +0.0000] | FAIL（境界） |

**読み方**：market に対する改善はほぼ全て favorite-longshot bias の power 補正
（b=1.065）から来ており、**fundamental の正味の寄与はゼロかむしろ負**
（a=0.017 ≒ 0、combined は market^b より有意に悪い）。

G1 では fundamental が素朴事前を大きく上回っている（1.2221 vs 1.3513）。つまり
fundamental は着順について実在する情報を学習している。**その情報が既にオッズへ
織り込まれている**というのがここでの結論。fundamental が使うのは公開データ
（勝率・モーター・展示タイム）＝投票者も見ている情報なので、整合的な結果。

#### 市場含意確率の検算（この判定の前提）

marginalize した q の較正を実測で確認済み。枠別 平均q vs 実勝率は
1号艇 0.5172/0.5286、6号艇 0.0371/0.0307。確率帯別も 0.0〜0.9 の全帯で一致。
Σq/レース = 1.0 ちょうど。**人気薄が過大評価される favorite-longshot bias が
教科書通りの向きで出ており**（6号艇を買いすぎ・1号艇を買わなさすぎ）、
これが b>1 の正体。市場側パイプラインにバグはない。

#### 合成器の推定法（重要な修正）

当初 `LogisticRegression` で合成器を推定していたが**これは誤り**。評価はレース内
softmax（条件付き多項）なのに LogisticRegression は艇ごとの二値分類を最適化する
別の目的関数で、両者が一致しない。結果 b=1.381 という歪んだ係数が選ばれ、
**市場単体より悪い合成（1.2167 vs 1.1686）**という本来ありえない値が出ていた。

条件付きロジット（McFadden。Benter が使ったのもこれ）なら a=0,b=1 で市場を厳密に
再現できるため、合成が市場を下回ることは原理的に起きない。`g2_prelim.py` と
`combine_market.py` の両方を条件付きロジットに修正済み。

#### 頑健性確認：本番 walk-forward の fundamental でも結果は変わらない

「予備の fundamental が単一窓1年学習で弱いせいではないか」を潰すため、LZH 遡り後の
データで全期間 walk-forward を再学習し（G1 も再確認: 199,130レースで 1.2182 vs
素朴 1.3500、CI [−0.1334, −0.1300] **PASS**）、その本番予測で同じ検定をやり直した。

```
uv run --with scipy python src/g2_prelim.py --use-wf
```

| | 単一窓1年学習 | 本番 walk-forward |
|---|---|---|
| fundamental 単体 log-loss | 1.2541 | 1.2536 |
| a(fundamental) | 0.017 | **0.019** |
| combined − market | −0.0011 [−0.0026, +0.0005] | **−0.0011 [−0.0027, +0.0005]** |

**ほぼ完全に一致**。fundamental の学習量を増やしても a は 0.02 前後から動かない。
「モデルが弱いから優位が出ない」ではなく、**情報が既に市場に入っている**が結論。

正式版 `combine_market.py`（月単位 walk-forward）も同じ符号だが、検定に使えるのが
202308 の389レースのみで検出力が出ない（−0.0010 [−0.0063, +0.0045]、a=0.019）。
予備判定の K-fold 版のほうが同じ結論を高い精度で出している。

#### この判定の限界

- **4,901レースしかない**。Benter の優位も効果量は小さく、検出には大標本を要した。
  ただし combined−market の CI幅は ±0.0016 と既にかなり狭く、
  **仮に真の改善があっても log-loss で 0.003 未満**という上限は言える
- 34日連続＝単月バイアス。季節・グレード構成が偏っている
- 使っている特徴量は公開データのみ。beforeinfo（チルト・部品交換・展示ST・
  スタート展示進入）は**未収集**で、これは投票者が見ていない/織り込みが薄い可能性が
  ある唯一の残り札。§8「beforeinfo の投入条件」に従えば、G2不合格時の第一の追加データ

### G0 実測結果（2026-07-19、51日分・8,234レースで検証済み）

- 1号艇勝率 52.4%。会場別最低=江戸川40.0%・最高=徳山68.6% — 公知の序列と一致
- 3連単の人気順位別的中数は単調減少、1番人気的中率10.4%（公知値9〜10%）
- **odds×100 = 払戻金 が98.9%で一致** → オッズHTML の組番復元式は正しい
- 全120通り均等買いの回収率は **59.1%**（75%ではない）。これはバグではなく
  favorite-longshot bias の実測値。均等買いは自動的に人気薄への過重賭けになる。
  当初の G0 定義（75%収束）は理論的に誤りだったので上記に差し替えた。

### 清算ルール（返還の扱い、実データで確認済み）

フライング/欠場艇が出ると、その艇絡みの組は**返還**され、プール再計算で
実払戻が表示最終オッズと乖離する（例: 20230701 江戸川2R、1号艇F、
表示87.7倍に対し実払戻19.4倍）。よってバックテストは2ソース分離：

- **購入判定** … odds3t の最終オッズ（＝締切前に見えていた情報）
- **清算** … K ファイルの払戻テーブル（真の払戻）。F/欠場艇絡みの購入は返還=全額戻し

fundamental 単体が市場に log-loss で負けるのは**想定内**（市場のほうが賢い）。
問われるのは「市場に自分の情報を足したとき、市場より良くなるか」だけ。

## 8. 検証運用の確定事項（2026-07-19 決定）

### 封印の開封プロトコル — 開封は1回のみ

1. 開封前に `PREREGISTRATION.md` を作成しコミットする。内容：
   - モデルのコミットハッシュ（コード・特徴量リスト・学習設定）

2. 開封 → 凍結済み設定で1回だけ実行 → 結果を無編集で記録
3. **失敗したらこの封印は焼失**。直近1年は walk-forward 用データに格下げし、
   次の検証は「これから先の未来データ」でしか作れない（プロスペクティブ移行）

### G4 の統計手続き（事前定義）

- 主指標: 均等賭け100円 ROI。レース単位ブートストラップ n=10,000、
  片側検定 ROI>100%、α=0.05
- オッズヘアカット 0/5/10/15% の4本を必ず併記。
  **主判定はヘアカット5%（保守側）で行う**（締切ズレ実測前の暫定値。

- グレー（ROI>100% だが CI が100%を跨ぐ）は**証明失敗として記録**。
  ただしモデルを凍結したまま新規未来データで追跡を続け、サンプルが
  埋まったら再判定してよい（凍結を崩した時点で追跡は無効）

### 締切ズレの実測（G2通過後のみ実施）

歴史データに締切前オッズは存在しない。G2通過後、開催中レースの

### オッズ帯の扱い

確率推定誤差は低確率帯で EV を系統的に過大評価する（推定pが真の2倍なら
EVも2倍に見える）。EV>閾値の目は人気薄に偏りやすい。対処：
**EV閾値とオッズ上限（50/100/200倍/なし）を walk-forward のグリッドで選び、
選択ルールごと事前登録して凍結**。封印側での調整は一切しない。

### 清算規則の完全列挙（バックテスト実装仕様）

| ケース | 検出 | 清算 |
|---|---|---|
| 通常的中 | payouts に組が存在 | 払戻額（オッズ表でなく払戻表の額） |
| 通常不的中 | - | 賭け金没収 |
| 返還 | rank_raw が F/K/L の艇絡みの組 | 賭け金全額戻し |

| 特払い・不成立 | payouts の特殊行 | **要実装確認**（3年分に出現するか調査してから） |
| レース中止 | K に結果行なし | 賭け対象外（B だけあるレースは購入しない） |

### 自己インパクトの扱い（G4 では補正不要）

G4 は100円均等賭け。3連単プールは1目あたり数万〜数十万円規模のため
100円のインパクトは <0.5% で無視できる。§6 のインパクト式は
「収益化のスケール上限試算」専用とし、G4 の判定には入れない。

### beforeinfo（チルト・部品交換・展示ST）の投入条件

boatrace.jp の同一ホストなのでオッズ収集と並走させない。
**G2 の結果が出てから**判断：不合格なら第一の追加データとして収集（約47時間）、
合格なら ablation 候補として後回し。

## 9. 主要リスク

- **G2 を通らない可能性が高い**。競艇AIの公開事例の大半は75%の壁を越えていない。
  控除率25%は極めて高いハードル。これは想定される最も確率の高い結末であり、
  そう終わっても「越えられないことを厳密に示した」なら成果として扱う。
- **スクレイピングの中断・仕様変更**。公式サイトの構造変更でパイプラインが壊れる。
  取得と解析を分離し、生HTMLを保存してから解析する構成にする。
- **オッズ取得が規約上グレー（2026-07-20 判明、§3参照）**。サイトポリシーが
  「大量のアクセス」を明示禁止、かつ Akamai Bot Manager 稼働中。全件取得は中止し
  標本化（方針A）に変更した。**このリスクは技術的に消せない** — レートを落としても
  規約違反は規約違反で、消せるのは事故の確率だけ。ゼロにする唯一の道は事前照会。
  最悪ケースは自宅IPのブロックで、テレボート（同一ドメイン）まで巻き添えになりうる。
  なお G2 が不合格ならオッズ収集自体が無駄になるため、**手持ち5,311件で G2 予備判定を
  先に回すのが、リスクと工数の両方を最小化する順序**。
- **リーク**。直前情報を使う設計上、時刻の扱いを一箇所でも間違えると未来が混入し、
  walk-forward が無意味になる。全特徴量に「いつ確定する情報か」を明記する。
- **封印の消耗**。開封のたびに情報が漏れる。回数を記録し、上限を守る。

## 13. 払戻から市場確率を復元する（2026-09-07）

オッズ板の収集が規約上の理由で止まっている（§3, §11）。だが**市場の log-loss は
板を使わずに全期間で計算できる**ことが分かったので、その経路と結果を記録する。

### 原理

log-loss は「実際に起きた目に割り当てた確率」しか使わない。的中目の市場確率は

```
q_realized = (1 / (払戻金/100)) / Σ_c (1/odds_c)
```

で出る。分母は本来120通り全部が要るが、控除率が固定なので**ほぼ定数**。
手持ちの完全板 5,238レースで実測:

```
Σ(1/odds)  mean 1.3368  sd 0.0018  min 1.3343  p50 1.3364  max 1.3497
```

中央値 1.3364 を定数として代用したときの復元誤差（返還・同着を除外後、
板のある 5,102レースで検証）:

```
log誤差  mean +0.00032  sd 0.00134  p1 -0.0014  p99 +0.0051
|log誤差| < 0.01 の割合: 100.000%
```

レースごとの加算定数として入るだけなので、20万レースで平均すれば SE は 1e-5 未満。
`payouts.parquet` は 224,034レース分の3連単払戻を持つので、**スクレイピングゼロで
217,027レース分の市場確率が手に入る**（返還6,961・同着72 を除外後）。

実装: `src/market_from_payouts.py` → `data/parsed/market_payout.parquet`

### 除外するレース

- **返還**（F/L/K を含む）: 当該艇の舟券が返還されプールが縮むため、購入判定時の
  オッズと清算の払戻が別物になる。除外しないと復元誤差の p99 が +1.29 まで膨らむ。
- **同着**（3連単の払戻行が2本以上）: プールが的中目に分割されるため。

### 単勝プールは使えない（棄却）

単勝の払戻からも同じ理屈で**勝率レベル**の q が出せる（6艇空間なので既存の G1/G2 と
直接比較できる）ため先に検討したが、板のあるレースで実測すると

```
log(1/o_単勝) - log(q_3連単周辺化)  mean +0.2283  sd 0.4010
```

平均 +0.228（正規化子 0.796 ≒ 法定の単勝払戻率80%）は理屈通りだが、**レース単位の
sd が 0.40** と、検定したい効果量（log-loss で 0.001〜0.003）を桁で上回る。
単勝プールが薄く市場推定の質が違う。3連単プールのみ使う。

### 測れないもの

**G2 本体（合成 vs 市場）はこの経路では測れない。** 合成 `P ∝ p^a·q^b` の正規化子
`Σ_c p_c^a q_c^b` に全120通りの q が要るため。a=0 周りのスコア検定にしても
`E_q[log p]` が要るので同じ。**板を買う/集める判断の前段**であって代わりではない。

### 結果（2026-09-07、199,053レース）

`src/gap_at_scale.py`。fundamental は既存の walk-forward 予測を Plackett-Luce で
120通りへ展開したもの。

```
===== 3連単120通り空間の log-loss =====
  市場（払戻由来 q）   : 3.6988
  fundamental (PL展開) : 4.0474
  素朴 (会場×枠, PL)   : 4.3624
  一様 (1/120)         : 4.7875

  fundamental - 市場 : +0.3486  95%CI [+0.3442, +0.3529]
  fundamental - 素朴 : -0.3150  95%CI [-0.3185, -0.3115]   ← G1 相当
```

年別に割っても穴は +0.334〜+0.360 で安定（2022〜2026）。

### 最重要: 穴の内訳（板のある 4,900レースで分解）

```
  1着だけ(6艇空間) の差   : +0.0849
  120通り空間の差         : +0.3888
  → 2・3着の条件付き部分  : +0.3039  (78%)
```

**穴の 78% は「1着を所与とした2・3着」にある。** fundamental が1着を当てる力の差は
2割しかない。原因は Plackett-Luce の IIA 仮定で、§2 で予告した通り競艇では露骨に
破れる（決まり手により2着以下の分布が変わる）。市場はこれを知っている。

**含意: 次に効くのは fundamental への特徴量追加（beforeinfo）ではなく、
段階条件付きモデル（§2 の拡張2）への置き換えである。** G2 予備判定が
「fundamental の正味寄与ゼロ」で終わったのは1着レベルの話であり、120通り空間には
まだ 0.30 の未回収分が残っている。順番を間違えないこと。

### 参考: オッズ非使用ルールの回収率（199,053レース、100円/点、厳密値）

的中目の払戻は K文書にあり外れは掛け金を失うだけなので、**オッズ板なしで
回収率を厳密に計算できる**。モデル確率の上位k点を買うルール:

|---|---|---|
| 1 | 8.73% | 82.51% |

| 3 | 22.03% | 81.42% |
| 5 | 31.44% | 81.51% |
| 10 | 47.21% | 79.54% |
| 20 | 64.60% | 77.28% |

パイプラインの相互検算になっている。控除率25%＝上限75%に対し、モデル上位を買うと
82%まで上がる（人気側に寄せることで favorite-longshot bias を避けている）が、
