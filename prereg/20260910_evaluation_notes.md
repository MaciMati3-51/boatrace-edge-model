# 結果取得後の評価手順

2026-09-10、結果を参照せず評価コードを準備した。事前登録本文・凍結予測は変更しない。

公式日次データを既存の取得・変換処理で `data/parsed/payouts.parquet` に反映した後:

```bash
.venv/bin/python src/evaluate_preregistered.py
```

`prereg/20260910_result.md` に実行時刻付きで追記する。ネットワークアクセスや結果取得はこのコマンドに含まない。6レースの通常2連複払戻が揃わない場合は pending。P1不合格ならP2/P3は集計しない。2連単の転記も保存してあるが、今回の主要評価は事前登録の2連複空間で行う。

実装上の補足（事前登録に具体的な計算法の指定がなかった部分）:

- 95%CIはレース単位で対を保つブートストラップ、10,000回、seed=0、百分位法。
- ROIは全点均等賭け。レース単位の払戻合計÷購入点数合計。購入ゼロは算出不可とし、再標本の購入点数合計がゼロの場合もCIから除外する。
- 同着・特殊払戻・人気2〜3の境界の同率は、通常ケースとして黙って処理せず要確認とする。今回のスクショには当該人気境界の同率なし。
- 若松11Rの撮影時刻問題を明記する。結果を見て対象を落とすことはしない。撮影時刻とオッズ更新時刻は `20260910_screenshots.json` に保存済み。
- P1不一致だけでは、撮影タイミング以外の転記ミス・返還等を排除できない。原画像・公式データの確認は別途必要。

検証: ` .venv/bin/python -m unittest discover -s tests -v `。人工払戻で一致・不一致・欠損・同着・外れ券・購入ゼロを確認し、実際の凍結予測との照合も確認した。実レースの結果は未参照。
