# 直前情報＋オッズ合成モデル v1

2026-09-12。出走表・過去履歴・直前情報からの確率に、2連単・2連複それぞれの市場確率を合成する処理を実装した。

## 時系列比較

baseモデルは7/19〜8/19で学習、合成係数は8/20〜8/31で推定、9/1〜9/9で比較。baseモデル開発時に9月の結果を見ているため探索的評価とする。

|券種|評価レース|モデル単体log-loss|市場補正log-loss|合成log-loss|合成の紙上回収率|
|---|---:|---:|---:|---:|---:|
|2連単|815|2.64006|2.63674|2.57533|82.99%|
|2連複|668|2.07312|2.16570|2.05632|96.01%|

log-lossは小さいほど良い。市場補正はオッズ逆数から作った確率をべき乗補正したもの。合成はnormalize(p^a q^b)。今回の比較では市場補正より改善したが、収益性は未達。

紙上購入ルールは「最終確率×取得時オッズ>1の全候補に各100円」。2連単は2,383点・238,300円に対して197,760円、2連複は1,743点・174,300円に対して167,350円の払戻。日単位bootstrapの回収率95%区間は、2連単69.81〜97.93%、2連複73.60〜117.77%。9日間だけの探索的な参考区間。

オッズ0・欠損の組は補完せず、その券種のレースを除外した。正常な6艇全艇完走だけの集計なので、欠場・返還などを含む全レースで同じ回収率になるとは言えない。市場のみ／市場補正のみのEV>1候補は0点で、回収率は算出不可。

## 保存モデル

- `data/models/live_v1/preview_model.pkl`: 出走表＋履歴＋直前情報、9/9まで学習。
- `data/models/live_v1/market_coefficients.json`: 8/20〜9/9の時系列外base予測を使い、各券種別に再推定した係数。評価に使った係数とは別。
- `data/models/live_v1/market_evaluation.parquet`: 各比較方法の確率・オッズ・紙上選択・払戻。
- `prereg/live_market_v1_result.json`: 全集計と区間。

## スクショ転記からの予測

出走表・直前情報は1艇1行のCSV、オッズは1組1行のCSVに転記する。入力形式は`data/models/live_v1/input_example.csv`と`odds_input_example.csv`。過去レースの見本なのでそのまま予測せず、新しいレースの値を入力する。部品・プロペラ交換は使わない。

```bash
OMP_NUM_THREADS=4 POLARS_MAX_THREADS=4 .venv/bin/python src/live_market.py predict \
  --input race.csv --odds odds.csv --out prereg/live_YYYYMMDD_JJ_RR
```

`fundamental.csv`にモデル単体確率、`final.csv`に券種別の最終確率・市場確率・期待値・紙上候補、JSONにモデル・入力ハッシュと生成時刻を保存する。自動投票はない。合成器とbaseモデルのハッシュ不一致、学習済み日付、欠けたオッズ板、予定締切後の取得データを拒否する。生成が締切前だったかは記録時刻と照合する。

10項目のテストで、確率の整合性、同日履歴の除外、展示F、進入入れ替わり、日時・オッズ欠損の拒否、保存モデルの読み戻し、最終予測経路を確認した。

運用投入候補はできたが、独立した今後の締切前予測で検証する必要がある。現行約20万レース学習モデルからの自動昇格や収益化達成は宣言しない。
