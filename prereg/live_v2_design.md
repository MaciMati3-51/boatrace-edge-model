## 4. 前向き検証（事前登録）

**対象**: 20260910 〜 取得できる最新日。v1・v2 とも再学習・係数変更なし。
**データ**: boatracecsv の直前情報（tkz・stt・sui・od2。取得日時が予定締切前60分以内のもの）、公式 B/K（mbrace）。
**標本**: 正常6艇完走、通常払戻1件、板が完全（2連複は2連単板も完全）。v1 は直前情報3ソースが揃うレースのみ予測できる。
**v1 の再現**: v1 の予測は `live_model.py` の読み込み・特徴量・`RaceModel.predict` をそのまま使う。
新しい日付の読み込みは `load_previews()` と同じ変換を別関数で行い、0719〜0909 で v1 の `dataset.parquet` と
一致することを先に確認する。

| | 指標 | 判定 |
|---|---|---|
| Q1（主） | v2 − v1運用 の log-loss（1着・2連単・2連複）。両方が予測できるレースで対応付き、日単位bootstrap 95% | 2連単・2連複の上限 < 0 なら「v2 が良い」 |
| Q2 | v2 合成 − 確定市場（券種別） | 閾値なし。点推定と区間を記録 |
| Q3 | v1ルール（v2 の P×撮影時オッズ>1）の買い目で、実現回収率と `ev_settle` 平均・`ev_captured` 平均 | 実現が `ev_settle` 平均のほうに近ければ「変動補正が効く」 |
| Q4 | 紙上回収率（各100円）: v1凍結ルール（v1 の P×撮影時オッズ>1）/ v2ルール（ev_settle>1） | 閾値なし。点数・回収率・区間を記録 |

**結論しないこと**: 収益性。前向き期間は約2週間で、v2ルールの買い目は数十点しか出ない見込み。
回収率の区間は ±50pt 程度になり、100%超えの有無は決まらない。

結果は `prereg/live_v2_prospective_result.md` に書く。この文書は書き換えない。

## 5. 運用（スクショからの予測）

入力は v1 と同じCSVでよい（v2 は出走表10列・展示タイム・取得時刻・締切時刻だけを使う）。
オッズは odds2tf ページの2連単30＋2連複15を両方転記する（2連複の合成に2連単板を使う）。

```bash
OMP_NUM_THREADS=6 .venv/bin/python src/live_market_v2.py predict \
  --input race.csv --odds odds.csv --out prereg/live_v2_YYYYMMDD_JJ_RR
```

`final.csv` の `ev_settle` が確定オッズでの期待値、`paper_candidate` はその >1。`ev_captured` と
`v1_rule_candidate` は比較用。撮影は締切9〜10分前が学習データ（od2 撮影の中央値9.4分前、5〜95%が8.4〜9.7分前）
と揃う。これより遅い撮影では市場が鋭くなり、合成の重みがモデル側に寄りすぎる。
